# 제품 확장 기획 — Monolith 운영 리허설 플랫폼

- 최초 기획: 2026-09-09. 통합: 2026-10-23.
- 상태: 향후 아이디어·요구사항 보관. 현재 테스트베드의 완료 조건이나 구현 일정이 아니다.
- 현재 저장소의 목적은 OpenStack·Kubernetes 테스트베드와 졸업작품 S1~S4 실험이다.
  제품화를 다시 추진할 때 이 문서에서 지원 범위와 구현 순서를 재검토한다.
- 기존 기획서와 PRD를 통합했다. 별도 PRD는 두지 않는다.

## 제품 의도와 범위

외부 개발자가 소스 코드와 예상 트래픽을 제출하면 고객 서비스의 월 운영 비용 초안을
먼저 제공하고, 격리된 실험으로 성능·용량·확장·복구 특성과 구성 대안을 확인하는 SaaS 구상이다.
현재 GCP·OpenStack·Kubernetes 기반 위에서 제한된 Monolith를 대상으로 시작한다.
초기에는 한 번에 한 실험을 실행하며 실제 고객용 앱·사용자 화면은 아직 구현하지 않았다.

필수 분석 입력은 소스 코드와 트래픽 설명 두 가지다. ZIP과 자연어 설명을 초기 입력안으로
두고 테스트 스크립트·SLO·클라우드 계정을 필수로 추가하지 않는다. 인증·이용 동의는 별도다.
지원 언어·DB·프레임워크·제품 스택·업로드 및 실행 상한·보존 기간·일정은 미정이다.

RPS가 명시되면 그대로 사용한다. 동시 사용자·방문자 수는 행동 빈도와 요청 수를 가정해
변환 근거를 표시한다. 목표가 불명확하면 탐색 결과만 제공한다. 코드로 확인한 사실,
사용자 입력, 가정, 미확인을 구분하며 정상 동작을 재현하지 못한 기능은 제외·보류한다.

| ID | 결과 | 사용자가 알 수 있는 내용 | 주요 조건과 한계 |
|---|---|---|---|
| O-01 | 예상 운영 비용 | 고객 서비스의 기본 월 비용, 변동 비용, 구성별 비용 | 가격표·배포 프로파일·가정 표시 |

| O-04 | 병목과 원인 후보 | 자원·DB·공유 구간의 포화 징후, 추가 조사 대상 | 관측과 원인 가설 구분 |

| O-06 | 확장 정책과 지연 | 감지·준비 시간, 확장 중 오류, 축소 결과 | 사양 변경·애플리케이션 증감·노드 증감 분리 |
| O-07 | 지속 실행과 복구 | 누적·악화 징후, 재시작·축소·복구 중 영향 | 실험 시간과 정의한 기능 범위에 한정 |
| O-08 | 구성 적정성과 비용 대안 | 최소·여유·복구 요구 후보의 성능과 비용 | 저사용률만으로 과설계 단정 금지 |
| O-09 | 개선 우선순위 | 권장 변경, 근거, 비용 변화, 재검증과 관측 방법 | 예상 효과와 검증된 효과 구분 |

기본 화면에는 목표 대응, 비용, 우선 문제, 검증된 추천과 미검증 범위를 먼저 보여준다.
새 분석·진행·결과·이력에서 조건을 수정하면 기존 결과를 덮어쓰지 않고 새 실행을 만든다.

코드·데이터·부하·워밍업·환경을 고정하고 사양과 실행 개수를 한꺼번에 바꾸지 않는다.
최고 통과 부하와 최대 용량, 관측과 원인 가설, 예상 효과와 검증된 추천을 구분한다.

## 결과 계약과 판정 상태

### 결과의 공통 필드

모든 판단은 실행 ID, 코드 식별값, 런북과 평가 프로파일 버전, 대상 기능, 데이터·트래픽 조건, 측정 환경, 측정 시간·표본 수, 근거 자료, 중요한 가정, 미검증 범위를 연결해야 한다.

비용 결과는 고객 배포 프로파일과 가격표 버전을 추가로 연결한다. 추천 결과는 기준 구성, 변경 내용, 비교 실행, 효과와 비용 변화, 적용 제약, 재검증 방법을 연결한다.

### 판정과 작업 상태 구분

| 판정 | 의미 |
|---|---|
| 기준 충족 | 유효한 실험에서 적용한 기준 충족 |
| 기준 미충족 | 유효한 실험에서 적용 기준 초과 |
| 탐색 결과 | 사업 목표 또는 적합한 평가 기준이 없어 측정·곡선 중심 제공 |
| 부분 검증 | 일부 기능·조건만 실험함 |
| 판정 보류 | 실험 유효성 또는 근거 부족 |
| 미검증 | 해당 실험을 수행하지 않음 |

작업 완료·실패·취소·시간 초과는 위 판정과 별개의 실행 상태다. 시스템 오류로 작업이 실패했다고 고객 서비스가 기준 미충족인 것은 아니다. 전체 보고서는 기능별 상태를 종합하며 미검증 항목을 통과로 승격하지 않는다.

### 지표 해석

- p90·p95·p99는 응답 지연 분포이며 적정 목표 자체가 아니다.
- 관측값, 목표값, 확장 기준, 경보 기준, 자원 제한을 구분한다.
- 요청 성공과 업무상 정상 처리의 범위를 명시한다.
- 자원 사용률에는 분모와 측정 구간을 표시한다.
- 표본 부족·반복 변동·부하 누락의 유효성 규칙은 버전별 정책으로 관리한다.
- 인스턴스 또는 반복 실행의 percentile을 단순 평균하지 않는다.
- 단기 실험을 월간 가용성이나 운영 환경 전체의 보장으로 표현하지 않는다.

## 고객 비용의 경계

고객의 배포 구성과 가격표를 기준으로 컴퓨팅·DB·저장·백업·네트워크·필요한 부가 인프라를
계산한다. 실험 플랫폼의 비용과 SaaS 이용료를 고객 운영 비용에 합산하지 않는다.
가격표 식별자·지역·통화·기준일·가동 시간·할인·세금·포함/제외 항목을 보존하며 미산정을
0원으로 표시하지 않는다. 피크 지속 시간이 없으면 시나리오·범위로 제시한다.
중첩 가상화의 성능을 고객 운영 환경과 같다고 가정하거나 논리 자원 절감을 실제 청구액
절감으로 자동 환산하지 않는다. 기반 호스트와 내부 VM의 비용도 중복 합산하지 않는다.

## 추진 순서와 제품 수용

A: 기준 Monolith와 관측으로 기반 포화와 앱 병목을 구분한다. B: 두 입력·비용 초안·
R-01~05·결과 비교를 MVP로 구현한다. C: 조건부 R-06~09를 추가한다.
D: 외부 베타 표본의 자동 완료율·개입 시간·첫 비용/결과 대기·판정 신뢰도·추천 효과·
이해도·재사용을 확인한 뒤 지원 범위를 넓힌다. 베타 없이 사업 수치 목표를 확정하지 않는다.

핵심 MVP의 외부 베타 수용에는 다음 조건이 모두 필요하다.

- [ ] 지원 범위와 지원 불가 사유가 사용자에게 공개되어 있다.
- [ ] 지원 프로젝트가 코드와 트래픽만으로 접수부터 유효한 핵심 결과까지 진행한다.
- [ ] 전체 성능 실험 완료 전에 고객 운영 비용 초안 또는 산정 제한 사유를 제공한다.
- [ ] 비용에 가격 근거·가정·포함 범위·미산정 항목이 표시된다.
- [ ] 사용자 수를 요청량으로 변환할 때 가정과 단위를 보존한다.
- [ ] 정상 동작을 검증하지 못한 기능을 전체 서비스 통과 근거로 사용하지 않는다.
- [ ] 기본 부하·단계 증가·구성 비교의 측정 조건과 원본 근거를 보존한다.
- [ ] 생성기·기반 포화 등 무효 실험을 통과로 판정하지 않는다.
- [ ] 검증된 추천에는 비교와 반복 실행의 근거가 있다.
- [ ] 9개 결과 영역에 실제 검증 상태를 표시하며 미실행 확장·복구를 통과로 표시하지 않는다.
- [ ] 고객 간 데이터 접근과 제출 코드의 관리 권한 접근을 차단한다.
- [ ] 취소·시간 초과·실행 재시도·정리 실패를 검증했다.
- [ ] 소스·자료 보존 기간과 실행 상한이 설정되어 있고 사용자에게 안내된다.
- [ ] 실행 자원 정리가 기존 persistent foundation을 대상으로 하지 않는다.
- [ ] 제품의 대표 흐름이 현재 레포의 구축 결과 위에서 실행되는 것을 확인했다.
- [ ] 적용한 기본 평가 기준이 고객의 사업 목표나 운영 보장으로 표현되지 않는다.

P1 출시에는 R-06~R-09의 조건부 실행, 결과 판정과 실패·중단 경로 검증을 추가한다. 체크리스트는 향후 검증할 항목이며 현재 완료했다는 의미가 아니다.

## 범위 밖과 재검토할 결정

MSA 전체 최적화, 모든 언어·DB·외부 의존성 지원, 임의 업무 규칙의 자동 이해, 고객 운영
환경의 직접 변경·배포·부하 주입, 자동 코드 수정, 보안 진단 제품, 운영 가용성·처리량·
정확한 청구액 보장, 무제한 탐색·다중 클라우드 최적화·과금 체계는 현재 구상 범위 밖이다.

제품 스택·첫 지원 코드/DB·비용 프로파일·평가 기준·실행 상한·보존/삭제 기간은 해당 기능을
시작하기 전에 결정한다. 외부 코드 수용 전에는 고객 간 접근, 관리 자격 접근, 자원 상한,
취소·재개·정리·비밀 노출·삭제를 검증해야 한다. 내부 실험의 무기한 증거 보존을 고객 정책으로
자동 적용하지 않는다. 기반 교체를 전제하지 않으며 기존 결정과 충돌하면 [ADR](../adr/README.md)로 기록한다.

실험 기반의 현재 과제는 [기반 운영 과제](infrastructure-priorities.md)를 따른다.
