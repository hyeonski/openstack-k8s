# 중간보고서 착수 점검 — 2026-09-26

## 판정

**S4를 구현·기본 검증한 중간보고서 작성은 지금 시작할 수 있다.** 이 판정은 저장소 코드, 로컬 실행 원본, 실환경 검증 기록을 점검한 결과다. 이번 점검 자체에서는 GCP 호스트를 기동하거나 새 장애를 주입하지 않았다.

중간보고서의 완료 범위는 OpenStack/Kubernetes 기반, 단일 worker VM 중단에 대한 실험 자동화, worker 전용 MHC 정책, Pod–Node–Machine–Nova 연결, Kubernetes/MHC/CAPI/CAPO 복구의 관측, HTTP 서비스와 worker 용량의 별도 완료 판정, 원본 기반 분석, 실행 후 정리다. S1~S3은 설계·최종보고서 목표다. VM 교체 자체는 MHC/CAPI/CAPO가 담당한다.

## 보고서에 사용할 수치

중간보고서의 서비스 복구 시간은 [장애 시나리오 정의서](failure-scenarios.md)의 기준에 따라 **첫 관측 실패부터 30초 이상 안정적인 HTTP 성공이 확인될 때까지**로 쓴다. 기존 자동 분석 표의 71.515~78.649초는 **첫 실패부터 첫 정상 응답까지**이므로 별도 항목으로 표시한다. 각 실행의 `analysis/summary.json` 시각 차이를 다시 계산했다.

| 실행 | 중단 뒤 HTTP 성공/전체 | 첫 실패→첫 정상 응답 | 첫 실패→안정화 확인 | VM `SHUTOFF` 확인→worker 용량 안정화 |
|---|---:|---:|---:|---:|
| `s4-e7a4fd084e56` | 197/226 | 71.515초 | **101.728초** | 246.697초 |
| `s4-055ac54a8adf` | 191/221 | 73.413초 | **104.437초** | 246.495초 |
| `s4-ec4f3851e726` | 182/212 | 78.649초 | **109.848초** | 245.000초 |

서비스와 용량 시간의 시작 사건이 다르므로 두 열의 값을 직접 빼서 “서비스가 worker보다 몇 초 빨랐다”고 계산하지 않는다. 비교 그림은 같은 UTC 시간축에 `stop-intent`, `SHUTOFF`, 첫 실패, 첫 성공, 안정화, 새 worker Ready를 표시한다. HTTP 시간은 약 1초 요청 시작과 5초 타임아웃으로 관측 공백이 있어 실제 중단 시간의 정확한 경계가 아니다.

## 보고서에서 분명히 밝힐 한계

1. HTTP 요청은 Kubernetes API Service proxy를 통과한다. 이 결과는 시험 서비스가 해당 경로에서 회복됐다는 근거이며, 일반 사용자 ingress의 중단 시간이나 성능은 아직 측정하지 않았다.
2. 세 실행은 구현 경로의 반복 확인이다. 실행 사이에 준비·분석 코드가 보완됐고 첫 실행에는 이후 추가된 코드 해시 기록이 없다. 동일 코드·조건의 통계 실험이나 장애 복구 성공률 100%로 해석하지 않는다.
3. `197/226` 등은 **장애를 포함한 실행 전체의 HTTP 요청 성공 비율**이다. 복구 실행의 성공률이나 정상 운영 가용성이 아니다.
4. 복구 동작은 Kubernetes와 MHC/CAPI/CAPO가 수행했다. 작품의 직접 구현은 정확한 대상 선택·실험·상태 연결·두 완료 조건의 독립 판정·자동 분석·안전한 정리다.
5. 상위 workflow의 중단·재개는 외부 명령 대역 테스트로 확인했다. 실제 실환경에서 의도적으로 실행기를 중단한 뒤 재개한 시험은 아직 없다.
6. 로컬 `artifacts/`는 Git에서 제외된다. 중간보고서의 표·그림을 만든 원본을 제출 또는 별도 보관할 때 실행 ID와 출처를 함께 보존해야 한다.

## 작성 착수 순서

1. [양식에 맞춘 기존 목차](interim-report-plan.md)를 쓰되, 서론과 요약의 시제를 현재 검증 상태로 바꾼다.
2. S4 구조도와 세 실행의 UTC 시간선, 직접 구현/기존 제어기 책임표를 직접 그린다. 그림은 양식 규격에 맞춘다.
3. 관련연구 국문 3편·영문 3편의 원문을 확인하고 문장별 인용을 붙인다. 현재 계획 문서의 공개 초록 검토만으로 관련연구 본문을 확정하지 않는다.
4. 4장에는 위 표와 원본 실행 ID를 사용하고, API proxy 경로와 표본 공백을 결과 분석에 명시한다.

따라서 **S4 코드를 더 구현해야 중간보고서를 시작할 수 있는 상태는 아니다.** 남은 일은 보고서 집필·그림·문헌 검토와 제출 형식 검증이다. 일반 사용자 ingress 실험과 실환경 중단 후 재개 검증은 결과를 더 넓게 주장하려 할 때 필요한 후속 검증으로 둔다.
