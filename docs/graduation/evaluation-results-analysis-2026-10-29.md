## 4. 분석

### 4.1 strict 회복 판정의 한계와 지표 선택

S1·S2의 무조치·비효과 arm은 위반율 약 2~3%에서 정상 상태처럼 일정하게 유지됐다. S1 bin(요청 100개)에서 위반율이 2.6%(S1 M 조치 후 위반율의 중앙값)이면, 한 bin이 5% 기준을 넘을(위반 6건 이상) 확률은 이항분포로 약 4.7%다. 위반율 2.5%에서는 약 4.0%, 6개 bin 모두 정상일 확률은 약 78%다. 마지막 6개 bin(120초)이 우연히 모두 정상일 확률은 약 0.953⁶ ≈ 75%다. 따라서 이 arm들의 strict "회복"은 상당 부분 **우연으로 결정**된다.

- 실제로 S1 M은 2/3, S2 S는 2/3이 회복으로 판정됐다. S2 S는 비슷한 위반율(2.6~3.0%)에서 회복과 미회복이 갈렸다.
- 회복 tail 시작 시각도 880~1040초로 H 끝 무렵에 몰려 있다.

그래서 S1·S2의 효과는 **조치 후 SLO 위반율**로 제시하고, strict 판정은 함께 공개한다. 이 지표는 사후에 정한 것이므로 논문에 명시한다.

### 4.2 R2: 계층 간 정보 기여

조치가 효과적이라는 것만으로 R2가 입증되지 않는다. R2를 입증하려면 그 조치를 단일 계층 정보로는 고르거나 실행할 수 없어야 한다.

| 시나리오 | 단일 계층 정보로 같은 조치가 가능한가 | 결론 |
|---|---|---|
| S1 | **대상 선택은 결과가 같아짐.** K8s는 host를 모르지만, worker가 2개이고 각각 다른 host에 있으므로 "다른 node로 옮긴다"는 K8s 규칙도 P와 같은 곳을 고른다. 반면 원인(같은 host의 다른 VM)은 K8s에서 관측되지 않고, K8s 기본 대응인 재시작(A)은 효과가 없었다. V1은 host 경합만 있고 서비스 영향이 없을 때 조치하지 않았다. | 대상 선택에서 정보 기여는 **현재 토폴로지에서 식별 불가**. 진단 측면은 정황 근거 |
| S2 | **불가능.** QoS를 걸 대상 port를 정하려면 Pod → VM → Neutron port 대응 정보가 필요하다. | 구성적 근거 |
| S3 | **불가능.** K8s는 Node NotReady만 안다. 기존 DB writer가 살아 있는지는 OpenStack VM 상태로만 알 수 있다. 실측에서도 NotReady인데 VM·DB 프로세스는 살아 있었다. | 구성적 근거 |
| S4 | 기존 기능이 이미 계층을 연결함 | 해당 없음 |

결론적으로 R2는 "S2·S3의 조치는 계층 간 대응 정보 없이 실행할 수 없으며, 실행했을 때 효과가 관측됐다"까지 말할 수 있다. "결합 정보 규칙이 단일 정보 규칙보다 나은 판단을 했다"는 비교 실험이 없어 말할 수 없다.

### 4.3 R3: 조치 기전

- **S1:** 같은 worker 재시작(A)은 효과가 없었고, 다른 host의 worker로 재배치(P)하면 기준선 수준으로 돌아왔다. 효과는 **경합 host에서 벗어난 것**에서 왔다.
- **S2:** "결합이 필수"는 두 조건이다.
  1. QoS가 필요하다 → **지지.** S가 효과 없었다.
  2. 분리가 필요하다 → **검증하지 않음.** QoS만 거는 arm이 없었다.

  P는 uploader를 분리한 worker의 port에만 QoS를 건다. 분리 없이 QoS를 걸면 API와 공유하는 port를 조이게 된다. 분리가 QoS 표적화에 필요하다는 것은 설계 의도로만 남는다.
- **S3:** fencing과 out-of-service의 개별 기여는 분리하지 않았다(범위 밖).

### 4.4 compute 사양 비대칭

ADR-0017에 따라 target compute01은 n2-standard-8, source compute02는 n2-standard-4다. S1 P의 조치 후 위반율과 p95(약 98~99ms bin p95)는 주입 전 기준선과 같은 수준이다. 그래서 "큰 host라서 기준선보다 더 좋아진" 추가 효과는 관측되지 않았다. 다만 설계상 비대칭은 공개하고, 동질 하드웨어에서의 보편적 효과로 일반화하지 않는다. 부하 발생기가 compute01의 CP VM에 있어 재배치 후 요청 경로가 짧아지지만, 기준선 대비 차이가 없으므로 영향은 무시할 수준이다.

## 6. 타당성 위협과 한계

- **표본:** 조건당 유효 2~4건. 보충·확장은 별도 cohort와 source에서 실행됐다. 섞어서 비교할 때는 그 사실을 표에 표시했다.
- **사후 요소:**
  - S1·S2 조치 후 위반율은 사후 지표다.
  - S2 S arm은 main 종료 후 추가한 실험이다.
  - 둘 다 원래 primary 판정을 대체하지 않는다.
- **무효와 재시도:** main 무효 8건은 서비스 미복구가 아니다. 다음이 섞여 있다.
  - Mac 경유 관측 경로의 연결·회수 실패
  - Mac NTP 시계 보정과 벽시계 기반 지연 계산의 결합(s3-b03-p3600)
  - 준비·정리 경로 실패
  - 분석기 예외(s2-b03-p)
  - case마다 worker VM을 다시 만들면서 생긴 Neutron SG 캐시 불일치

  보충은 무효 원본마다 별도 회차로 실행했다. 유효한 미복구 결과는 재실행하지 않았다. 결측 편향의 가능성은 공개한다.
- **운영 변경:** 11개 source cohort에 걸쳐 읽기 예산, clock guard, SG 캐시 정합 등을 보완했다. 측정 계약(SLO·H·부하·bin)은 고정했지만 운영 보완이 측정에 완전히 중립이라고 가정하지 않는다.
- **토폴로지:** worker 2개, host 3대의 고정 fixture다. R2 대상 선택을 식별하려면 같은 host에 대체 worker가 있는 구성이 필요하다.
- **검증하지 않은 것:** 사람과의 비교(R6), 규모·장시간·부하 민감도(R7), 장애 주입형 강건성 시험(R5 확장).
