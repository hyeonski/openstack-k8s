`artifacts/`는 Git 추적 대상이 아니므로 위 경로는 로컬 실험 원본을 가리키며 GitHub에서 열리는 링크가 아니다. 첫 관측 HTTP 실패부터 첫 정상 응답까지는 각 회차 76.108초, 81.409초, 81.356초였다.

세 회차의 stop 요청→`SHUTOFF` 확인은 각각 73.946초, 68.707초, 69.456초다. 첫 관측 HTTP 실패는 `SHUTOFF`보다 각각 64.599초, 59.667초, 59.262초 앞섰다. 같은 워커 안정화 시각을 stop 요청 기준으로 계산하면 320.926초, 320.670초, 326.705초이고 첫 실패 기준으로는 311.579초, 311.630초, 316.511초다. `SHUTOFF` 기준 시간은 확인된 전원 꺼짐 뒤 구간이며 실제 용량 손실의 정확한 시작 시각은 기록하지 않았다. HTTP 실패의 분류는 API proxy 연결·시간 초과가 세 회차 모두 8건, `no endpoints available`이 각각 21건, 25건, 25건이다. 중단 전 HTTP 기준선에는 실패가 없었다. 시간 초과의 마지막 요청 시작은 Node Unknown보다 5.1~5.9초 앞서거나 첫 회차에서만 0.5초 뒤였고, `no endpoints available`의 첫 요청 시작은 Node Unknown 뒤 0.2~6.6초였다. 이 순서는 복구 과정과 상응하지만 각 네트워크 구간의 원인을 독립적으로 증명하지는 않는다.

HTTP 클라이언트는 각 응답 또는 타임아웃 뒤 1초를 기다리며 요청 타임아웃은 5초다. 세 회차 모두 2.5초 초과 표본 간격이 8곳씩 있어 표의 밀리초 자릿수를 실제 회복 경계의 정밀도로 해석하지 않는다. HTTP 경로는 Kubernetes API Service proxy이며 일반 사용자 ingress를 측정하지 않았다. 서비스와 워커 시간은 시작 사건이 달라 서로 빼서 단계 간 간격을 구하지 않는다. 각 원본의 `run.json`, `http.jsonl`, `observations/`, `result.json`, `analysis/summary.json`, `finalization.json`을 결과 근거로 사용했다. 환경 종료 확인은 S4 복구 결과 판정과 구분한다. 앞선 두 회차의 종료 상태를 재검증할 별도 상태 파일은 현재 남아 있지 않다.
