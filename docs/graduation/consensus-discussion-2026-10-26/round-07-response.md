# 7라운드: 구축·실행 상세안 최종 승인 검토

두 문서를 전부 읽었습니다. 이번 라운드는 읽기만 했고 파일을 수정하거나 실험을 실행하지 않았습니다.

## 1. 착수할 수 있는 수준인가

착수할 수 있습니다.

**무엇을, 어느 파일에:**
- 구축안 3절 B01~B11에 작업별 파일, 변경점, 완료 조건이 있습니다.
- 내가 코드에서 확인한 함정 네 가지가 모두 명시돼 있습니다.
  - `case.py:316`의 1,080초 하드코딩
  - `verify_s1`의 5,400 하드코딩과 새 기대값 9,000
  - `schedule()`의 KeyError와 기존 34개 ID 회귀 테스트
  - `PROFILE`이 hash 대상에서 빠지는 문제
- adapter를 쓰고 raw는 재작성하지 않는다는 원칙, 기존 `no-action` 모드를 재사용한다는 결정도 반영됐습니다.

**어떻게 검증하는가:**
- 구축안 6절의 검증 표가 핵심 위험을 모두 덮습니다. M이 H 안에서 미복구여도 유효한 run으로 남는지, 재악화, 시각 역순, 응답 소실, 정리 실패, 사람 슬롯 결측이 각각 들어 있습니다.

**어떤 순서·군·목적으로:**
- 실행안 2~4절에 비교군별로 같게 둘 조건, 달리할 조건, 허용되는 주장, 금지되는 확대가 있습니다.
- 시나리오별 절차와 run 공통 SOP도 있습니다.

**환경 의존 값:**
- 구축안 8절 표에 각 값의 결정 시점과 근거가 정리돼 있습니다.
- 값이 null이면 profile validator가 freeze를 거절하고, G3 gate가 이를 막습니다.

- transient의 992분과 1,258분은 당신의 정정이 맞습니다. 6라운드에서 내가 쓴 942분과 1,208분은 시나리오 분리 원칙을 지키지 않은 값이었습니다.
- run 수도 맞습니다. 본시험은 29 / 25 / 11회, 준비·pilot은 8 / 8 / 2회입니다.
- 구현 노동의 B01~B06 합은 20~30시간으로 문서 값과 일치합니다.

막는 문제는 아니지만 명확히 해 두면 좋은 점이 두 가지 있습니다.

**(i) 세션 A 안에서 pilot manifest에서 main manifest로 넘어가는 순서**
- G3는 pilot과 main을 서로 다른 frozen manifest로 관리하라고 합니다. 그리고 S1의 main freeze는 하나여야 합니다.
- 그렇다면 세션 A는 다음 순서여야 합니다.
  1. 자동 smoke와 V1 pilot (pilot manifest)
  2. 세션 안에서 main freeze. source는 그대로 두고, 등록된 parameter만 채웁니다.
  3. V1 main과 block 1
- 7절 표의 나열 순서가 이와 일치하므로 지금 문서로도 실행할 수 있습니다. 다만 다음 문장을 추가하기를 권합니다.
  > "세션 내 pilot→main 전환은 source 무변경·사전 등록 parameter 기입만 허용하며, 그 freeze 소요시간은 운영 50분에 포함한다."

**(ii) 정책과 계측이 같은 파일에 섞여 있는 문제**
- 예를 들어 `experiments/graduation_s3.py`에는 판단 코드와 계측 코드가 함께 있습니다.
- 문서 규칙에 따르면, S1 main이 시작된 뒤 이 파일의 계측만 고쳐도 정책 수정으로 분류됩니다. 보수적이고 일관된 규칙이라 모순은 아닙니다.
- 다만 이 규칙 때문에 S3를 시나리오별 freeze로 고칠 수 있는 여지가 사실상 사라집니다. 그래서 B02 단계에서 첫 main 전에 계측을 정책 파일 밖으로 분리하기를 **권장**합니다. 필수는 아닙니다.

> "Codex와 Claude가 새 평가 체계의 구축 상세안과 실행 상세안까지 합의해 문서화했다. 구현·pilot·본시험은 아직 수행하지 않았고, 범위(F-repeated / F-bounded / F-S1)·일정·예산·사람 참여는 사용자가 G0에서 선택해야 한다. 20시간 안에서는 S1 부분 평가만 가능하며 전체 작품 평가는 약 30~33시간이 필요하다."

**승인: 새 평가 체계 구축 상세안과 새 평가 실행 상세안의 현재 내용에 동의한다. 실제 범위·일정·예산 및 pilot 값 확정은 실행 의존성이며 설계 합의의 미해결 쟁점은 아니다.**
