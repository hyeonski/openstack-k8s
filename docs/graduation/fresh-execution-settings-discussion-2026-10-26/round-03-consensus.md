## 문서에 꼭 넣어야 할 조건 네 가지

1. **"21:00 이후 새 case 시작 금지"는 코드가 막지 않습니다.**
   - 지금 코드가 확인하는 것은 주입 시각(`last_injection_utc` = 13:00Z)과 host 수명뿐입니다.
   - 실행 담당이 run 진입 gate로 `last_case_start_utc = 2026-10-28T12:00:00Z`를 구현하거나, 최소한 운영 규칙으로 강제해야 합니다.
   - 그 gate에는 "실측 준비 + 관측 + 정리 시간 + host down 시간"이 자정 전에 끝나는지 확인하는 조건도 함께 넣어야 합니다.
2. **직렬 진행의 달력 여유는 작습니다.**
   - 10/26 15:35부터 10/28 21:00까지 가용 시간은 약 53.4h입니다.
   - 여기서 사전 보완 구현(DEV, baseline, secondary 차이), 첫 기동, 직렬 33.4h, 재pilot 6.2h를 빼면 여유가 몇 시간뿐입니다. 밤에도 무중단으로 운영한다는 전제입니다.
   - 사전 보완 구현에 실제로 걸린 시간을 반영해, DEV를 시작하는 시점에 "재pilot 1회를 감당할 수 있는가"를 다시 계산하도록 적어 두십시오. 감당할 수 없다면 재pilot이 필요해지는 순간 사용자와 협의합니다.
3. **2개 bed는 조건을 모두 충족할 때만 진행합니다.** B를 쓰려면 다음이 모두 갖춰져야 합니다.
   - project B의 billing, 크레딧 적용, quota 확인
   - 이미지 복사본의 무결성 검증
   - 5번의 원자적 예약 coordinator
   - bed B 자신의 go/no-go 통과

   하나라도 늦어지면 직렬로 남습니다. B 배포에 쓴 시간도 48h 합산과 비용 원장에 넣습니다.
4. **report와 분석은 host 없이 할 수 있습니다.** 다만 frozen 실행 checkout에서 해야 합니다. 그래서 자정 이후 보고서를 쓰는 동안에도 그 checkout과 hash 대상 docs는 수정하지 않습니다. 보고서와 발표자료는 다른 checkout이나 경로에서 작성합니다.

이 네 가지를 포함하면 설정 합의를 닫는 데 동의합니다.
