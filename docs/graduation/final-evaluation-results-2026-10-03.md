## 제외하지 않고 보존한 예외

- `s1-no-action-01`: IAP 연결 오류로 경합 진단 전에 중단됐다. 1,954개 요청 원본을 보존했으며 완결된 성능 측정이 아니다. 실패 시도 분모에 포함하고, 유효한 무조치 반복으로 세지 않는다.
- `s2-dynamic-first-02`: 10Mbps 구간 측정 후 호스트 지표 조회에서 Google Compute API 연결 시간이 초과됐다. 기준선·무제어 2구간·6Mbps 구간의 원본 480개 요청만 완전하게 저장됐다. 고정/동적 비교는 미완결이며 성능 비교와 정상 성공률에 넣지 않는다. 이 실패 시도는 분모에 남기고 재실행으로 대체하지 않는다. 유효한 S2 순서별 표본 수가 달라지는 제한도 반영해야 한다.
- `s2-fixed-first-01`: 본 측정 시작 전 준비 과정의 management 조회가 실패했다. 실제 상태와 소유권을 확인해 원상 복원한 뒤 명시적으로 준비를 재개했다. 원래 준비 로그와 reconciliation 기록을 보존했다. 최초 오류의 근본 원인은 확정하지 않았다.
- `s1-automatic-02`: 측정 시작 전 첫 namespace 조회에서 로컬 API 터널 연결이 거절됐다. 이 중단 당시 새 S1 준비·측정 기록은 생성되지 않았다. 원래 준비·터널 오류 로그를 보존하고, 이전 시나리오 기록 불변과 auto 1대 복원을 독립 대조한 뒤 같은 예정 시험의 준비를 재개했다. 원격 연결 종료/Broken pipe의 근본 원인은 확정하지 않았다.
- `s3-automatic-02`: 최초 워커 준비 중 TLS 연결 시간이 초과됐다. 당시 새 측정·장애 주입은 시작되지 않았고 실제 워커도 1대였다. 준비 오류 원본을 보존하고 worker auto/1 및 자원 정리를 재검증했다. 오류 시각인 2026-10-03 18:06:56 KST에 로컬 Software Sleep 기록이 있지만 유일한 근본 원인으로 확정하지 않는다. 사용자의 중단 요청으로 준비를 보류했고, 이후 같은 예정 시험의 재개를 승인받았다. 재개 후 검증된 결과는 위 표에 표시한다.
- `s4-interrupt-resume`: 의도적으로 프로세스를 중단한 시험이다. 같은 실행·대상으로 재개됐지만 관측 공백은 `incomplete`/`completed_with_gap`으로 남겼다. 정상 반복 성능 통계에 합산하지 않는다.
- `s4-normal-04`: 최초 준비에서 worker 2대 확장과 준비 검사 후 management API의 worker 배치 조회가 TLS 시간 초과로 실패했다. 새 S4 측정·장애 주입 전에 발생했으며 이전 S4 실행·준비·워크플로 기록은 그대로였다. 오류 원본을 보존하고 소유 worker를 auto/1로 복원·검증한 뒤 같은 예정 시험의 준비를 재개했다. 연결 오류의 근본 원인은 확정하지 않았다.
- `s2-fixed-first-05`: 최초 준비의 새 compute01 worker DNS 검사가 실패했다. 같은 worker에서 반복한 12회 질의는 개입 전에 모두 성공했으므로 최초 실패의 원인은 확정하지 않았다. 별도 확인에서는 기존 compute02 worker의 IP가 compute01 보안 그룹 주소 목록에서 누락됐고 그 worker의 DNS 12회가 모두 실패했다. 기존 compute01 Neutron 에이전트 한 개를 재시작해 목록을 재동기화한 뒤 두 worker에서 각각 같은 질의 12회가 통과했다. 설정·이미지·이전 S2 기록을 보존하고 준비 자원과 worker auto/1 복원을 검증한 후 본 측정을 재개했다. 주소 동기화 누락이 반복된 근본 원인은 미확정이다.
- `s1-no-action-04`: 측정 종료 후 worker 축소의 DNS 검사에서 실패했다. compute01의 worker 보안 그룹 주소 목록(ipset)이 비어 있었고 동일 worker의 DNS 서비스·CoreDNS 직접 조회 12회가 모두 실패했다. 기존 Neutron 에이전트만 재시작해 주소 목록을 재동기화한 뒤 같은 조회 12회와 전체 준비 검사가 통과했다. 보안 그룹 정의·컨테이너 이미지·측정 파일 불변, worker auto/1 및 잔여 자원 제거를 독립 검증했다. 측정을 재실행하지 않았으므로 유효한 무조치 자료로 유지하지만, 사람 개입 없이 정리까지 성공한 실행으로 세지 않는다. 주소 목록이 비게 된 최초 원인은 아직 확정하지 않았다.
